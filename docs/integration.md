## Почему Go исполняет рекомендации

В backend-ветке уже существовали чистые Go-пакеты расчёта и camelCase HTTP DTO.
Оформленного контракта вызова Python из Go не было.
Вместо второго процесса исправлены и дополнены Go progress/recommendation, а UI подключён к существующим HTTP-маршрутам.
Python-модуль из main сохранён как offline reference с теми же полями dataset, ограничениями gain, датой среза,
проверкой eligibility и критической ступенью сортировки.

UI только преобразует DTO для отображения. Он не начисляет навыки, не изменяет score и не пересортировывает рекомендации.
Завершение вызывает Go API, который сохраняет запись и возвращает пересчитанный профиль и рекомендации.
Чтение состояния использует независимый снимок под блокировкой, чтобы конкурентные completion не меняли читаемые карты.

## Фактические данные и расхождение prerequisites

Файлы data перенесены без изменения содержимого:
200 employees, 40 events, 60 skills, 32 role_profiles, 2743 activity records.
Из 40 мероприятий 4 mandatory, 36 optional, 9 self_paced, 12 имеют skill prerequisites.

В events.json:

- target_roles и target_grades — массивы строк.
- develops_skills — массив объектов skill_id/gain/max_level.
- prerequisites — объект skill_id → integer minimum level.
- upcoming_sessions — массив дат YYYY-MM-DD.
- format — online/offline/self_paced; отдельного boolean self_paced нет.
- type=mentoring обозначает менторство; отдельного boolean mentoring нет.
- career_goal сотрудника содержит target_role/target_grade.
- required_skills и critical_skills находятся в role_profiles файла skills.json.
- история использует date/record_id, а не occurred_on/completion_id.

Требование «prerequisites — завершённые мероприятия» не подтверждается официальным файлом.
Чтобы поддержать оба правила без подмены смысла данных, добавлено необязательное prerequisite_events: string[].
Каждый такой ID должен существовать и иметь completed у сотрудника на дату среза.
В официальном dataset этого расширения нет; его поведение проверяют регрессионные тесты.

## Ранжирование

1. Mandatory, неподходящая аудитория, невыполненные prerequisites, недоступная дата и ранее завершённые события исключаются. Исключение повтора — EV_036.
2. Нужен положительный эффективный gain в skill gap, либо fallback при отсутствии всех gaps.
3. Сначала сравнивается наличие критического положительного покрытия, затем total, gapScore и eventId.
4. gapScore = сумма эффективного покрытия, вес critical=2,5, остальных=1.
5. Сохраняются баллы исходного Go-модуля: совпадение с целью 5 (иначе 2), история формата completed +2 и no_show/dropped/declined −5, доступность 1–3.
6. Сортировка детерминирована; выбор «разнообразных форматов» удалён, поскольку он мог вытеснять критический gap.

Fallback: критические hard-навыки целевого профиля, soft-skills или type=mentoring.
Он не снимает требования аудитории, дат, prerequisites и неповторяемости.
Если каталог вообще не содержит доступных событий, система возвращает пустой список. Минимум одно событие нельзя гарантировать без нарушения фильтров.

## Объяснения

Без LLM_EXPLANATION_URL Go сразу возвращает ru/kk шаблон.
Для существующего LLM gateway задаются LLM_EXPLANATION_URL и необязательный LLM_API_KEY.
Сервер отправляет POST JSON:

```json
{"locale":"ru","recommendations":[{"eventId":"EV_005","title":"...","score":{},"evidence":{},"explanation":"..."}]}
```

В реальном запросе score/evidence содержат полный готовый DTO. Gateway возвращает только объект eventId → текст:

```json
{"EV_005":"Локализованное объяснение"}
```

Бюджет на все объяснения одного ответа — 1,4 секунды с запасом до 1,5. Ошибка, пустой текст или таймаут возвращают шаблон.
Score/evidence передаются отдельной копией; провайдер не может изменить вычисленные факты.
Число одновременно незавершённых обращений ограничено. Внешний gateway не нужен для штатного запуска приложения.
Проверены HTTP-контракт локальным тестовым сервером, ошибка провайдера, изменение копии и таймаут провайдера, игнорирующего отмену.
Настоящая внешняя LLM не проверялась: адрес и ключ не предоставлены.

## Ограничения текущего MVP

- Хранилище в памяти: завершения теряются при перезапуске.
- X-Demo-Role — контракт демонстрации, не защита для публичного сервиса.
- Снимок навыков хранит последнюю оценку: для даты раньше last_review_date нет исторического восстановления.
- Названия мероприятий и навыков отображаются как в официальном англоязычном каталоге; UI и объяснения — ru/kk.
- Источником истины в приложении является Go; Python не участвует в HTTP-запросах.
