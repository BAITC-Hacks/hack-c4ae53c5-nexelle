# Career Quest

Python-модуль карьерных рекомендаций: проверяет доступность мероприятий, рассчитывает пробелы в навыках и возвращает до трёх рекомендаций с детерминированным evidence. Объяснения доступны на русском и казахском.

## Стек и границы реализации

Python 3.11+, стандартная библиотека, unittest. Ruff и mypy используются при разработке.
Реализованы импорт JSON/CSV, рекомендации, пересчёт навыков, шаблоны и асинхронный интерфейс подключения LLM.
REST API, авторизация Employee/HR, постоянное хранилище, веб-интерфейс и конкретный LLM-провайдер пока не реализованы.
Production dataset в репозитории отсутствует; тестовые данные используются только в тестах.

## Запуск

Поместите исходные файлы в каталог `data/` согласно [контракту данных](docs/data-contract.md).
Значение максимального уровня берётся из спецификации dataset; приложение не подставляет его автоматически.

```powershell
$env:ABSOLUTE_MAX_SKILL_LEVEL = Read-Host "Максимальный уровень навыка из спецификации"
python -m backend --data-dir data --employee-id EMPLOYEE_ID --cutoff-date 2026-10-01 --locale ru
```

Или передайте максимум через `--absolute-max-skill-level`. Для казахского используйте `--locale kk`.
`.env.example` описывает переменную окружения; файл `.env` автоматически не загружается.
Результат CLI — JSON; ошибка данных возвращает ненулевой код завершения.

## Проверки

```sh
python -m pip install -r requirements-dev.txt
python -m unittest discover -s backend -t . -v
python -m ruff check backend
python -m ruff format --check backend
python -m mypy
python -m compileall -q backend
```

## Структура

- `backend/models.py` — доменные модели, DTO результата и evidence.
- `backend/data_loader.py` — строгий импорт и проверка ссылок.
- `backend/recommendation_engine.py` — eligibility, fallback, скоринг.
- `backend/progress.py` — чистая функция завершения мероприятия.
- `backend/ai_agent.py` — шаблоны ru/kk и адаптер объяснений.
- `backend/__main__.py` — CLI.
- `backend/test_backend.py` — регрессионные тесты.

## Правила

Дата среза обязательна и не берётся из системных часов. История после неё не влияет на рекомендации.
Без явной карьерной цели используется следующий грейд текущей роли; для Lead — Lead.
Критический разрыв образует отдельную первую ступень сортировки. Внутри ступени:
`score = 100 × sum(effective_gap_coverage) − penalties`.
Штрафы: `no_show=15`, `dropped=10`, `declined=5` за каждую запись.
При равенстве баллов порядок определяется `event_id`.

При отсутствии разрывов включается fallback: критические hard-навыки, soft-навыки, менторство.
Его балл — 30 за каждую подходящую категорию минус штрафы.
Общие фильтры сохраняются: если допустимых мероприятий нет вообще, результат пуст.
Система не придумывает мероприятия и не обходит prerequisites ради количества.

Завершение использует оба потолка уровня; мероприятия без навыков записываются в историю.
`completion_id` обеспечивает повторную обработку без начисления. Клуб `EV_036` допускает новое завершение с новым ID.
Вызывающий сервис должен атомарно сохранить обновлённый профиль и историю.

Адаптер объяснений ждёт LLM не более 1,4 секунды, оставляя время до лимита 1,5 секунды на возврат готового шаблона.
Провайдер должен использовать неблокирующий I/O. LLM получает готовую рекомендацию и возвращает только текст;
он не участвует в eligibility, score или evidence. Без подключённого провайдера шаблон возвращается сразу.
